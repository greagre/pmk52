# pmk52 — линия Б3-34: Б3-34 → МК-54 → МК-52

Эмулятор советских программируемых микрокалькуляторов **линии 34-го** на одном ядре RPN:
профили моделей, выбор модели в интерфейсе, документированные команды, тесты раньше интерфейса.

Проект выделен из `greagre/mk-emulator`, который остаётся **эталоном Б3-34** и не трогается.

## Линия 61-го — в другом проекте

С 23.11.2026 семейство разделено на две линии, и это разделение окончательное:

| Проект | Линия | Профили |
|:---|:---|:---|
| `mk-emulator` | Б3-34 | эталон 34-го, **не трогаем** |
| **`pmk52`** (этот) | Б3-34 → МК-54 → МК-52 | `b3-34`, `mk-54`, `mk-52`, `ext52` |
| [`pmk61`](https://github.com/greagre/pmk61) | МК-61 | `mk-61`, `ext61` |

**Профиль МК-61 сюда не добавлять.** У 61-й машины своя косвенная адресация, 15 регистров и
105 шагов — она живёт и развивается в `pmk61`, чтобы правка одной линии не ломала другую.

## Модели этой линии

| Модель | Шагов | Регистров | Статус |
|:---|---:|---:|:---|
| Б3-34 | 98 | 14 | профиль из mk-emulator |
| МК-54 | 98 | 14 | то же, что Б3-34 (другая маркировка) |
| МК-51 | 98 | 14 | упрощённый вариант, позже, пределы уточнить |
| МК-52 | 512 | 15 | целевой профиль, расширенная память |
| **ext52** | настраивается | банки | наша импровизация: развитие этой линии |

`ext52` — не историческая модель. Это наше продолжение линии 34-го: блоки памяти, страницы ППЗУ,
страницы программы. В интерфейсе он подписывается как экспериментальный, чтобы импровизация
не выглядела историей.

## Правила проекта

1. **Только документированные команды.** Если кода нет в таблице команд модели — он не выполняется
   и декодер помечает его как неизвестный с подписью, hex и причиной. Недокументированные
   возможности (регистр X2, «циклы» адресов A5–F9, шестнадцатеричная арифметика) в профили
   не попадают; если понадобятся — отдельным флагом, выключенным по умолчанию.
2. **Точность выше удобства.** Профиль реальной модели не расширяется: программа, которая
   не влезает в 98 шагов на настоящем Б3-34, не должна «работать» в его профиле.
3. **Расширения — только в `ext52`.** Новые шаги, банки регистров, страницы живут там,
   а не внутри профилей реальных моделей.
4. **Тесты раньше интерфейса.** Контрольные программы прогоняются на каждом профиле.
5. **Одиночный формат файла программ** (см. ниже), кодер и декодер работают через профиль.
6. **Ядро меняется только при доказанном баге**, различия моделей живут в `profiles.js`.

## Карта кодов (общая для семейства)

Регистры: `R0–R9` = `0–9`, `Ra` = «−», `Rb` = L, `Rc` = C, `Rd` = D, `Re` = E.

| Диапазон | Смысл |
|:---|:---|
| `1r` | `x→П r` — запись в регистр |
| `lr` | `П→x r` — чтение из регистра |
| `2r` | `К x→П r` — запись с восстановлением X |
| `3r` | `К П→x r` — чтение с сохранением в X |
| `4r` | `x→П r` |
| `6r` | `П→x r` |
| `Lr` (`Ar`) | `К x→П r` — косвенная запись |
| `Dr` | `К П→x r` — косвенное чтение |
| `7r` | БП по условию `x≠0` |
| `8r` | БП по условию `x≥0` |
| `9r` | БП по условию `x≤0` (в приложении «Все команды» указано `x≥0` — расхождение, требует проверки) |
| `Cr` | БП по условию `x<0` |
| `Er` | БП по условию `x=0` |
| `-r` (`Fr`) | ПП — вызов подпрограммы |
| `F0–FF` | пустой оператор |

Полная таблица 256 кодов с подписями, аргументами и разметкой `hidden` лежит в `profiles.js`
(`mapNames`, `mapHints`, `N`, `D`, `H`). Источник — приложение «Все команды» (ссылка ниже).

### Семантика, которую нельзя перепутать

- **Условный переход:** условие выполнено → адрес пропускается, выполняется следующая команда;
  условие не выполнено → переход по адресу.
- **Косвенная адресация:** модификация номера регистра — `R0–R3`: −1, `R4–R6`: +1, `R7–Re`: без
  изменений. Происходит только когда адрес реально вычисляется (у условий — при невыполнении).
- **Стек:** X, Y, Z, T + X1. Двухместная операция: T→Z, Z→Y, X→X1, результат→X.
- **В↑** дублирует X (T теряется). `↔` меняет X и Y. `F↔` — кольцо T→Z→Y→X→T.
- **Подпрограммы:** стек возврата 5 ячеек, `В/О` берёт верхний +1. После включения `В/О` ≡ `БП 01`.
- `0C` — **ВП** (ввод порядка), а не `В↑`.
- `24` (`x^y`) не сокращает стек; `К max` считает ноль наибольшим; `К СЧ` не даёт 0 и 1;
  в логических (37–3A) первая цифра принудительно 8, шестнадцатеричная арифметика, стек не сокращается.

## Формат файла программ

```json
{
  "app": "pmk52",
  "format": "programs",
  "version": 2,
  "model": "mk52",
  "saved": "2026-11-23T14:54:00+03:00",
  "programs": [
    { "name": "факториал", "prog": [1, 65, 97, 96, 18, 65, 93, 0, 2, 97, 80],
      "data": { "0": 7 }, "layout": { "n": 0 }, "inputs": [0], "src": "...", "savedAt": "..." }
  ]
}
```

Импорт понимает и старый одиночный формат `{prog, data, ...}`. Формат общий с `pmk61` —
файл программы переносится между линиями через поле `model`.

## Порядок работ

1. ~~Перенос ядра и обвязки из `mk-emulator`~~ — `core.js` перенесён, параметры моделей вынесены.
2. ~~`profiles.js`: профили `b3-34`, `mk-54`, `mk-52`, `ext52`~~ — сделано, таблица 256 кодов.
3. Сверка `core.js` с таблицей кодов: какие коды ядро реально исполняет и совпадают ли подписи.
4. Разбор в документации, как МК-52 адресует 512 шагов (две цифры в команде при 512 ячейках).
5. Профиль `mk-52`: 512 шагов, блоки памяти.
6. `ext52`: страницы программы и банки регистров — без смены формата команды.
7. Кодер и декодер — на таблице из профиля, один для всей линии.
8. Шина ввода/вывода: порты, лента выводов ЦАП, панель приборов.

## Известные расхождения, требующие проверки

1. Код `9r`: в таблице клавиш — `x≤0`, в приложении «Все команды» — `x≥0`. В `profiles.js`
   сейчас стоит `x≥0` (по приложению); при сверке с ядром решить окончательно.
2. Код `21` / `22`: в приложении «Все команды» `x²` указан как `21`, в таблице клавиш `21` — корень.
   Принято: `21` = `√`, `22` = `x²`.
3. В старом репозитории `calculator` (`b3-34.js`) условные переходы стоят на адрес при **истинном**
   условии — расходится с документацией; после переноса перепроверено и исправлено.
